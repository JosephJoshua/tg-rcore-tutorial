# Ch3-Ch5 SMP Implementation Plan

> **For Claude:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** Add symmetric multi-processing (SMP) support to chapters 3, 4, and 5 so all 4 QEMU harts participate in scheduling and executing tasks/processes.

**Architecture:** Coarse-grained locking with `SpinLockIrq` (interrupt-safe spinlock). Each chapter becomes a new standalone crate. Boot pattern from ch2-smp: hart 0 initializes, signals secondaries, all harts enter scheduling loop. Task execution happens outside the lock to minimize contention.

**Tech Stack:** Rust no_std, RISC-V 64-bit bare metal, QEMU virt platform with `-smp 4`, `tg-kernel-context` for context switching, `tg-kernel-vm` for Sv39 page tables (ch4/ch5), `tg-task-manage` for process management (ch5).

## Task 2: Create smp.rs for ch3-smp

**Files:**
- Create: `jsph-tg-rcore-tutorial-ch3-smp/src/smp.rs`

This module provides all SMP primitives shared across the scheduling code:

1. `SpinLockIrq<T>` - generic interrupt-safe spinlock wrapping data `T`
   - `lock()` -> `SpinLockIrqGuard<T>` (disables SIE before acquiring, TTAS spin)
   - Guard implements `Deref`/`DerefMut` and restores SIE on Drop
   - `const fn new(data: T)` for static initialization

2. `RawSpinLockIrq` - bare lock without data (for PRINT_LOCK)
   - `lock()` -> `RawSpinLockIrqGuard` (same interrupt-disable pattern)

3. `hart_id() -> usize` - reads `tp` register

4. `BOOT_HART_DONE: AtomicBool` - boot handshake flag

5. `PRINT_LOCK: RawSpinLockIrq` - console output serialization

6. `NUM_HARTS: usize = 4` constant

**Implementation notes:**
- On non-riscv64 targets, `hart_id()` returns 0 and lock skips CSR ops
- SpinLockIrq must save/restore the SIE bit, not unconditionally enable it
- The guard must release the spinlock BEFORE restoring interrupts (otherwise an interrupt could fire while the lock is still held)

## Task 3: Rewrite ch3-smp main.rs

**Files:**
- Modify: `jsph-tg-rcore-tutorial-ch3-smp/src/main.rs`
- Modify: `jsph-tg-rcore-tutorial-ch3-smp/src/task.rs`

**Key changes from original ch3:**

### _start assembly (replace single-core entry)
```rust
#[unsafe(naked)]
unsafe extern "C" fn _start() -> ! {
    const STACK_SIZE: usize = 8 * 4096; // 32 KiB per hart
    const NUM_HARTS_CONST: usize = 4;
    #[unsafe(link_section = ".boot.stack")]
    static mut HART_STACKS: [[u8; STACK_SIZE]; NUM_HARTS_CONST] = [[0; STACK_SIZE]; NUM_HARTS_CONST];

    core::arch::naked_asm!(
        "mv   tp, a0",
        "la   t0, {stacks}",
        "li   t1, {stack_size}",
        "addi t2, a0, 1",
        "mul  t1, t1, t2",
        "add  sp, t0, t1",
        "bnez a0, {secondary}",
        "j    {main}",
        stacks     = sym HART_STACKS,
        stack_size = const STACK_SIZE,
        main       = sym rust_main,
        secondary  = sym secondary_main,
    )
}
```

### rust_main (hart 0 only)
1. `zero_bss()`
2. Init console, syscall handlers
3. Load apps into shared scheduler state (wrapped in `SpinLockIrq`)
4. Enable timer interrupts: `sie::set_stimer()`
5. `BOOT_HART_DONE.store(true, Release)`
6. Fall into `scheduling_loop()`

### secondary_main
1. Spin on `BOOT_HART_DONE` with Acquire
2. Enable timer interrupts: `sie::set_stimer()`
3. Print "[Hart N] online" with PRINT_LOCK
4. Fall into `scheduling_loop()`

### SharedScheduler (protected by SpinLockIrq)
```rust
struct SharedState {
    ready_queue: VecDeque<usize>,
    tcbs: [TaskControlBlock; APP_CAPACITY],
    finished_count: usize,
    total_tasks: usize,
    syscall_counts: [[u32; 500]; APP_CAPACITY],
}
```

### scheduling_loop()
```rust
fn scheduling_loop() -> ! {
    loop {
        let task_idx = {
            let mut guard = SCHEDULER.lock();
            guard.ready_queue.pop_front()
        };
        match task_idx {
            Some(idx) => {
                tg_sbi::set_timer(riscv::register::time::read64() + 12500);
                // Execute OUTSIDE the lock
                let tcb_ptr = { /* get raw pointer to tcb under lock */ };
                unsafe { (*tcb_ptr).execute() };
                // Handle trap result
                match scause::read().cause() {
                    Timer => { /* re-enqueue */ }
                    UserEnvCall => { /* handle syscall, re-enqueue or finish */ }
                    _ => { /* finish (killed) */ }
                }
            }
            None => {
                let done = SCHEDULER.lock().finished_count >= SCHEDULER.lock().total_tasks;
                if done {
                    if hart_id() == 0 { tg_sbi::shutdown(false); }
                    else { loop { unsafe { core::arch::asm!("wfi") }; } }
                }
                core::hint::spin_loop();
            }
        }
    }
}
```

### task.rs changes
- Remove `pub static mut SYSCALL_COUNTS` global (move into SharedState)
- `handle_syscall` takes syscall_counts slice as parameter instead of global

### Console output
Wrap `Console::put_char` with PRINT_LOCK acquisition.

## Task 6: Rewrite ch4-smp main.rs

**Files:**
- Modify: `jsph-tg-rcore-tutorial-ch4-smp/src/main.rs`
- Modify: `jsph-tg-rcore-tutorial-ch4-smp/src/process.rs`

**Key changes from original ch4:**

### _start assembly
Same multi-hart pattern as ch3-smp (HART_STACKS in .boot.stack).

### rust_main (hart 0)
1. `zero_bss()`
2. Init console, kernel heap allocator
3. Allocate portal pages
4. Build kernel address space, activate Sv39
5. Init syscall handlers
6. Load ELF apps into processes (wrapped in SpinLockIrq)
7. `BOOT_HART_DONE.store(true, Release)`
8. Fall into `scheduling_loop()`

### secondary_main
1. Spin on BOOT_HART_DONE
2. **Important**: Do NOT write satp yet (kernel space already active from hart 0)
3. Actually, need to set satp for this hart too since hart 0 set satp for itself only
4. Read kernel satp value from a shared atomic and set it
5. Enable timer, fall into scheduling_loop

### Process list: SpinLockIrq<Vec<Process>>
Replace `ProcessList(UnsafeCell<Vec<Process>>)` with `SpinLockIrq<Vec<Process>>`.

### scheduling_loop (ch4 version)
Similar to ch3 but:
- Uses `ForeignContext.execute(portal, ())` instead of `LocalContext.execute()`
- Portal is initialized once by hart 0, address is shared
- Each hart's satp changes independently during portal execution
- Address translation for syscalls accesses process's address_space under lock

### Allocator safety
The `tg-kernel-alloc` global allocator has NO internal locking. We need to wrap it.
Options:
- (a) Add a SpinLockIrq wrapper around the GlobalAlloc impl calls
- (b) Use a global ALLOC_LOCK that the kernel acquires around alloc/dealloc

Approach (b) is simpler - add `ALLOC_LOCK: RawSpinLockIrq` and wrap `Sv39Manager::page_alloc()` calls.

### SYSCALL_COUNTS
Move to per-process or wrap in SpinLockIrq (ch4 has single `[u32; 500]`).

## Task 9: Rewrite ch5-smp main.rs

**Files:**
- Modify: `jsph-tg-rcore-tutorial-ch5-smp/src/main.rs`
- Modify: `jsph-tg-rcore-tutorial-ch5-smp/src/processor.rs`
- Modify: `jsph-tg-rcore-tutorial-ch5-smp/src/process.rs`

**Key changes from original ch5:**

### processor.rs: Per-hart current + SpinLockIrq wrapper
```rust
static PROCESSOR: SpinLockIrq<PManager<Process, ProcManager>> = ...;
static PER_HART_CURRENT: [AtomicUsize; NUM_HARTS] = ...;
```

The original `Processor` wrapper with `UnsafeCell` is replaced by `SpinLockIrq`. The `PManager.current` field becomes irrelevant; instead we track current process per-hart in `PER_HART_CURRENT`.

### main.rs scheduling loop
```rust
loop {
    let task = {
        let mut proc = PROCESSOR.lock();
        proc.find_next()  // returns &mut Process
    };
    // Problem: find_next() returns a reference into the locked PManager
    // We need the lock held during execute() for the process data
    // But we can't hold it during execute() (long-running, blocks other harts)
}
```

**Critical design challenge**: `find_next()` returns a mutable reference to a Process inside PManager. We can't drop the lock while still using that reference. Solutions:

**(A) Extract what we need under lock, release, execute:**
- Under lock: `find_next()`, get raw pointer to context, set PER_HART_CURRENT
- Release lock
- Execute via raw pointer (process won't be deallocated while running)
- Re-acquire lock for post-execution handling

This is the right approach. The process is "Running" so no other hart will touch it.

### Syscall handlers
All `PROCESSOR.get_mut()` calls become `PROCESSOR.lock()`. But during syscall handling, the current process is already identified by `PER_HART_CURRENT[hartid]`, so we can lock, get the process, handle the syscall, unlock.

For fork/exec/wait/spawn: lock around the entire operation (coarse-grained).

### process.rs changes
- `fork()` and `from_elf()` call the allocator (needs ALLOC_LOCK same as ch4)
- `map_portal()` reads KERNEL_SPACE (read-only after init, safe without lock)

## Implementation Order

1. **Ch3-smp first** (Tasks 1-4): Simplest - flat task array, no VM, no process tree
2. **Ch4-smp second** (Tasks 5-7): Adds VM complexity but same scheduling pattern
3. **Ch5-smp last** (Tasks 8-10): Adds process management - most complex

Each chapter builds on the previous: smp.rs is shared, scheduling pattern is refined.
